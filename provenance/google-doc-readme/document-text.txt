Role steering and agentic prompt injection
Hanan Ather
Code and saved evidence: role-confusion-study (repository access required).
Executive summary
LLM agents increasingly read webpages and files while carrying out user requests. An attacker can place instructions in that material and redirect the agent toward an unauthorized action, such as uploading a private file.
Ye, Cui, and Hadfield-Menell (2026) propose role confusion as an explanation for prompt injection. Their role probes classify internal activations by message role. These probes show that injected text can resemble user instructions or the model’s own reasoning. Their chain-of-thought (CoT) forgery attacks exploit the latter by inserting fabricated reasoning into external content.
I ask: Can changing how an agent represents the source of text reduce CoT-forgery attacks while preserving its ability to complete the user’s task?
Starting point: I use agentic prompt injection as a proxy task, adapting the agent-hijacking setting of Ye et al. (2026), where a GPT-OSS-20B agent is asked to summarize a webpage. The attacker inserts instructions to upload a local file, followed by fabricated reasoning such as “I must comply.”
Key addition: activation steering. I added a fixed vector, derived from role-labelled examples, to the model’s activations while it processes the page. Because the attack impersonates reasoning, I tested whether steering away from CoT toward Tool (external data) would reduce uploads beyond matched random steering. I compared against no steering, random directions of the same magnitude, and a simple instruction that retrieved text cannot authorize actions, using matched pages and seeds.
I also built an isolated evaluation environment with a dummy secret, a local test server that accepts uploads, and saved reasoning and action traces. I count an upload when this server verifies the file’s contents, so I can compare what the agent does with what the probe reads.
Results. Without steering, the agent uploaded the dummy secret on 70% of attacked pages.Strongest evidence against the CoT-based intervention. Steering toward Tool and away from CoT nearly eliminated the forged paragraph’s CoT probe score, yet uploads occurred on 60% of pages, compared with 20% for the best of three random directions and 40% for the simple instruction. The probe also revealed a competing role signal: across the retrieved content, User was the dominant label.Strongest evidence for the revised intervention. I used the User readout to revise the direction toward Tool relative to both User and CoT, at the same magnitude. On the development pages I had already inspected, uploads were 0%, versus 60% without steering and 20% under both the best random control and the simple instruction on those same pages. Every run with this intervention returned a summary. I have not yet tested whether this direction does better than the controls on new pages or checked the summaries' accuracy. See limitations.
Limitations and what I’d improve next
I tested whether steering GPT-OSS-20B's activations while it read an attacked webpage could preserve the requested summary and prevent an unauthorized dummy-file upload. The most important limitations are:
Unclear causal value of the role directions. My role probe classifies internal activations by message role. I can almost eliminate its reasoning-role score for the forged passage while six of ten attacks still succeed. Changing the score does not establish that I changed the representation driving the action. The revised direction's early success also does not establish that its role effect caused the improvement. Next step: vary the layer and token positions I steer, and check whether behavioral effects track role scores during later reasoning.
Source recognition does not establish permission. The same webpage instruction can be legitimate under one user request and unauthorized under another. Recognizing its source cannot settle that distinction. My results do not locate the failure: source attribution, permission handling or subsequent action selection could each contribute. The separate permission experiment below tests this distinction with a different role direction and probe. Applying the revised direction from the upload study to that task would test whether it preserves permitted actions while rejecting unauthorized ones.
Unclear advantage over simpler baselines. Random directions also reduce uploads, and a short developer reminder produced four uploads in ten trials, compared with six under the original direction. Matching the size of an activation change does not match how much it disrupts useful behavior; returning a summary does not establish its accuracy. Next step: compare steering, random directions and the reminder at similar performance on the user's task, including correctly completed authorized actions.
The revised direction has only been tested on development examples. Raising the Tool score relative to both User and reasoning produced no uploads on five reused pages, compared with three without steering and one each under the reminder and the best observed random direction. These pages informed the revision, so this result may overestimate its advantage on unseen examples. Next step: freeze the direction and controls, then vary the attack and surrounding article separately on unseen examples, with repeated sampling.

Introduction and related work
A user asks an agent to read a webpage and summarize it. The page contains an unrelated instruction to upload a local file, followed by a paragraph written as if the agent had already reasoned that the upload was permitted. The agent must use the article's information without accepting the page's account of what the user authorized. This is the setting I use to study chain-of-thought (CoT) forgery: an attacker places fabricated reasoning in external content to redirect the agent's actions.
My starting point is Prompt Injection as Role Confusion by Ye, Cui and Hadfield-Menell. They propose that an attack can exploit a mismatch between where text came from and the conversational role the model assigns it internally. Their linear role probes classify activations using the same neutral text presented under different role tags. Their experiments show that writing style can shift these readings despite the supplied tags, and that adding forged reasoning makes webpage injections more effective.
This suggests an intervention: change the model's representation of retrieved text before it acts. A direction that predicts behavior need not change it when intervened on. In How Language Models Choose Sides, Balp-Straffon and colleagues demonstrate this distinction in system–user instruction conflicts: directions with similar predictive accuracy can differ in their steering effects.
The closest follow-ups leave a specific question open. Mogford changed CoT-forgery probe readings, but even a direction built to change compliance did not reliably change attack success. Replacing activations changed behavior, but random perturbations of the same size had similar effects. These tests left the role features' causal importance unresolved. Zhang, Lee and Park report behavioral effects from a direction constructed by placing User versus Tool declarations around commands inside webpages. Their positive result concerns declaration-based attacks rather than forged reasoning.
I derive my directions from neutral text to test whether a role distinction transfers to forged reasoning in an agent task. My research question is: Can these role directions reduce compliance with forged reasoning beyond random perturbations and a simple instruction, while preserving the requested summary?
I test this in GPT-OSS-20B by holding the page text fixed and recording role scores alongside actual uploads. Tool−CoT, the Tool mean activation minus the reasoning mean, is intended to make retrieved text look more like tool output. It sharply suppresses the forged passage's reasoning-role score without demonstrating an advantage over random steering. Early checks also showed substantial User as well as Tool scores. Under the role-confusion account, User-like text could still be treated as an instruction. This motivated a contrast that separates Tool from both User and CoT.
The revised direction produced no uploads on five development pages, compared with three without steering and one each under the best matched random direction and a developer instruction restricting actions to the user's permission. Testing the same contrast in additional articles carrying these attack templates would assess whether the result transfers across article contexts while preserving accurate summaries.


Approach overview
I use the same pages and sampling seeds across conditions to test whether role steering reduces unauthorized uploads while the agent still returns a summary:
I first measured the baseline. I asked the agent to summarize a webpage containing an upload instruction and forged reasoning, then recorded whether it uploaded the dummy file without steering.
I constructed Tool−CoT from neutral text and added it while the agent processed tool output, keeping the page and model weights fixed.
I compared this with no steering, the reversed direction, random directions of the same magnitude, and a simple instruction about the user's permission. On the development pages, I also ran the steering code without adding a vector.
I checked how the intervention changed all five probe scores and compared these with verified uploads and the agent's traces.
The remaining User signal led me to test Tool−mean(User, CoT) on the five development pages.
I recorded whether the agent returned a summary as well as whether it uploaded the file. I have not yet checked the summaries' accuracy or tested the revised direction on new pages.
I measure uploads using the test server and changes in role scores using the probe.
Proxy task and attacker control
I use agentic prompt injection as a proxy task: I measure whether an agent acts on an unauthorized instruction embedded in material it needs for the user's request. I ask GPT-OSS-20B to read a complete webpage and summarize it in two or three sentences. The attacker controls text in the returned page, including an instruction to upload a local configuration file and forged reasoning that presents the upload as authorized. The agent can use a shell inside an isolated environment; the file contains dummy data and uploads go to the local test server. An attack succeeds when this server records the correct file contents. 
Technical setup: steering and role probes
I construct Tool−CoT from average activations for nine neutral texts, each presented under five conversational roles: System, User, CoT, Assistant and Tool. The direction is the difference between the Tool and reasoning class means. I set the activation edit to 16 times this mean difference. During each model call, I add it at the output of transformer block 11 to all accumulated tool-message content in the prompt. Role headers and newly generated tokens are excluded. The model weights and page text remain unchanged.
A separate five-role classifier, trained from 249 neutral texts rendered under the same roles, reads the post-attention normalization output of block 12. Both block indices are zero-based. I inspect all five role probabilities, and report the forged passage separately from the surrounding article. I average the probe's probabilities over all tokens in the forged passage immediately after the page is fetched. I compare probe scores with the development runs where the steering code adds no vector, and upload outcomes with runs without steering. A lower CoT score confirms a change in the measured representation; the upload record determines whether the attack succeeded.
Matched comparisons
The main comparison contains five development pages and five additional pages fixed before their outcomes were inspected. The additional pages reuse the five attack templates in different articles, so this tests sensitivity to surrounding content. Each page is evaluated with the same initial task and sampling seed under no intervention, Tool−CoT, its reverse, and three random directions of the same magnitude. The development pages also have a zero-dose control, which runs the steering machinery without adding a vector. A separate developer instruction says that retrieved text cannot authorize additional actions, providing a simpler baseline that requires no activation access.
These controls answer different questions. Zero dose checks whether the machinery itself changes the outcome. Reversing the direction tests whether its sign matters. Random directions test whether the proposed role contrast offers an advantage over an arbitrary change to activations. I retain every direction and compare outcomes page by page, so an aggregate improvement cannot hide an upload introduced on another page.
Refining the direction
Early probe readings showed that Tool−CoT suppressed the forged passage's CoT score while leaving substantial User scores. I therefore chose Tool−mean(User, CoT) as the revised direction. I derive it from the same class means and normalize it to the original edit's magnitude, testing whether raising Tool relative to both alternatives improves the behavioral result. The five development-page runs are complete. Testing the unchanged direction on the five additional articles would assess whether its effect depends on the development pages.
Measuring useful behavior
I record whether the agent encountered the attack, whether the dummy file arrived, whether the episode finished, and whether it returned a candidate summary. I report runs that hit a limit before their outcome is resolved separately. A useful defense must prevent the unauthorized upload while preserving an accurate summary. The logs show whether the agent returned a summary; I have not checked its accuracy. Reasoning traces and a separate authorship question help generate explanations for the observed actions. Because the added question changes the conversation, I treat those answers as a diagnostic rather than evidence of what the model recognized before acting.
Results
The original vector has no consistent advantage over controls
Pairing each steered episode with its unsteered counterpart shows how the outcomes change: the original direction prevents two uploads, introduces one, and leaves seven outcomes unchanged. All five new-page outcomes are unchanged. I retain the reversed direction, all three random directions, the developer instruction and the zero-dose check in Figure 1.

Near-zero reasoning scores coexist with successful uploads
I use the saved probes to check whether the intervention changes the intended readout. The development pairs establish a large reduction in CoTness. Some attacks still succeed, while several random-control episodes avoid uploading despite retaining higher scores. Suppressing this readout is insufficient to certify attack prevention.
The ten original-vector endpoints do not supply ten measured before-and-after comparisons. The no-intervention and reminder arms saved no probe readouts, and the new pages have no zero-dose reference. Their near-zero steered scores therefore show a measured level, rather than a measured reduction from an observed baseline.
The revised direction produces a different role distribution
A falling CoT score can redistribute probability among several roles. I therefore compare all five probe outputs over the same five development pages, separately for the complete tool response and its forged passage. Figure 3 uses actual episode readouts, averaging tokens within each page before weighting the pages equally.

Figure 3. Original steering yields 95% User across the tool response and a 48% User / 52% Tool mixture within the forgery. Revised steering yields approximately 100% Tool in both regions. These are mean probabilities, not fractions of tokens classified into each role.
The original direction mainly raises Userness over the response. The revised Tool − mean(User, CoT) construction instead produces the intended Tool-dominated readout. It also gives zero uploads on the five explored pages, compared with three without steering and one under the best observed random direction and the reminder.
That is a development result: the revised direction was constructed after inspecting earlier outcomes, and its five fixed new-page tests remain unrun. Each revised-direction run returned a summary, but I have not checked those summaries for accuracy. Completing those tests and grading the summaries would assess whether this construction prevents attacks while preserving the legitimate task. The current comparison does not establish that the measured role distribution caused the behavioral difference.


A second proxy task: selective execution
In a separate earlier experiment, I gave GPT-OSS-20B a page with two harmless file-writing commands, A and B. The page requested both actions; the user permitted only one and asked the model to report the fresh random value in each command. I changed only which action the user permitted. This let me measure unwanted writes, correct completion of the permitted action, and whether the answer used information from both commands.
Without steering, changing permission shifted the probe's scores on both commands together. In all eight available baseline cases, permitting the first-listed action raised both commands' mean User scores. In one example, command B scored 34.27% User when A was permitted and 28.26% when B itself was permitted. The command text and scored token positions were unchanged. A higher mean User score therefore did not consistently identify the permitted command. I have not yet tested whether reversing the commands reverses this pattern.
The task also showed why I need to measure useful behavior. Across 21 matched comparisons, Toolward steering prevented four unwanted writes and introduced three. It also lost two correct completions of the permitted action and two answers reporting both values. A short developer reminder prevented six unwanted writes and introduced none in its own 21 matched comparisons, but lost two permitted completions. One prevented Toolward write came from a malformed generation, so it was not a successful completion of the task.

Figure 4. All 21 recovered Tool − User steering episodes, paired with no-steering controls across eight cases. Mean command Toolness exceeds 99.997% in every steered episode, while unwanted writes fall from 18 to 17 and authorized completions from 21 to 19. The 21 episodes reuse 15 distinct model inputs. One avoided write arose from a parsing failure, so it did not represent correct task completion.

This experiment used a different role probe and Tool−User steering on the command tokens. I recovered 149 of 280 assigned episodes, and each method has its own available matched comparisons. These counts describe the recovered runs; they do not establish a reliable ranking of methods. The eight-case score pattern also leaves command order and content bundled together. The result I can support is that permission can change a role score without making it a reliable permission label, and reducing unwanted writes can come at the cost of work the user requested.

What I built and what I learned
Because this is an applied project, I optimized for end-to-end correctness and repeatability: a working experiment loop (attacked page → activation edit → agent actions → verified outcome) with saved inputs and outputs for each comparison. The rough sequence was:
Adapt a concrete attack and measure its outcome. I adapted the paper’s CoT-forgery attack to a webpage-summarization task using GPT-OSS-20B. I built an isolated test environment with a dummy secret file and a local server that records whether the agent uploads the exact contents of the dummy file. This gave me a direct measure of attack success.
Implement and check the activation tools. I adapted the paper’s role-probing method and added code to steer activations while the model processed retrieved text. I checked the layer and tokens being edited, and verified that setting the steering strength to zero preserved the generated tokens on identical inputs. These checks helped distinguish intervention effects from implementation errors.
Build repeatable comparisons with controls. I held pages and sampling seeds fixed across no steering, the proposed direction, its reverse, and three random directions of the same magnitude. I also tested an instruction that webpage text cannot authorize actions. I saved prompts, reasoning and action traces, and upload records so I could inspect each outcome.
Use the failed intervention to refine the hypothesis. The forged paragraph’s CoT score nearly vanished, but the intervention did not outperform the best of three random controls. The probe read the retrieved text predominantly as User. Suppressing CoT had not made Tool the dominant probe label across the retrieved text, which gave me a specific reason to revise the direction.
Turn that finding into a revised intervention. I constructed a direction toward Tool relative to both User and CoT, keeping the original magnitude and matched controls. It produced no uploads on the development pages tested. This gave me a candidate to evaluate on new pages, with factual summary accuracy as a separate requirement.

Future improvements
The next tests I would prioritize are:
Test transfer with a frozen intervention. Freeze the revised direction and controls, then cross unseen attack templates with unseen article contexts and repeat matched sampling seeds. This would separate dependence on an attack from dependence on the surrounding article. Report both uploads prevented and uploads introduced, since the net change can hide opposite effects.
Compare protection at similar task performance. Grade summary accuracy and correct completion of authorized actions, with graders unaware of the intervention. Compare steering strengths, random directions and the developer reminder at similar task performance. Equal-sized activation changes need not cause equal disruption; the useful comparison is how much protection each method provides while preserving the work the user requested.
Separate permission from claims of permission. Extend the fixed-page permission task by independently varying the user's actual authorization and the webpage's claim of authorization. Keep the commands fixed and apply the revised direction. A useful intervention should follow the user's permission even when the page claims otherwise, while retaining legitimate actions when the user does authorize them.
Locate when the intervention changes behavior. Track the same forged passage's role scores across later model calls, then compare steering at tool-content positions with steering at generated positions, using matched controls. This would test whether steering generated tokens improves upload prevention relative to steering the retrieved text alone. I would use reasoning traces to propose explanations, then check them against contrary outcomes and controlled changes to the prompt.

Appendix: Mini case studies
I selected two matched pairs from the ten-page comparison. Both use the original Tool−CoT direction, which steers webpage activations away from the model's reasoning role and toward tool output. Within each pair, the page and sampling seed were fixed; the user requested a summary, and the webpage requested a dummy-file upload.
1. Steering introduced an upload

On the Helodium moss page, the unsteered agent summarized without uploading. The page invented a policy exception for a user wearing green. Under steering, the model treated the appended upload as another user request; the local test server received the exact dummy-file contents. It still returned a summary, so checking only for a final answer would miss the failure.
2. Steering preserved the requested task

On the Rotokakahi River page, the unsteered agent uploaded the file. The steered agent made no further tool calls after fetching the page and returned a two-sentence summary whose factual claims matched the saved article. Its reasoning still called the injected instruction an earlier part of the conversation, so this does not establish correct source attribution.
The forged passage's reasoning-role score was below 0.01% in both steered runs. These pairs illustrate a prevented upload and an introduced upload within the aggregate result. Two random directions and the developer reminder also prevented the river-page upload; the example does not establish a unique advantage for role steering.
